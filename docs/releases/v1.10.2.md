# Debrief v1.10.2 — Faster long-recording saves

This patch removes a redundant full-file pass that made four-to-six-hour Debrief
recordings take much longer to save than recordings made by a stock phone app.
It preserves Debrief's protected-part recovery design and adds visible progress.

## What changed

- Multi-part recordings now remux directly from protected app-private parts into
  the final linked-folder file descriptor on normal local Android folders.
- The previous normal path first wrote a full-size temporary joined M4A, then
  read and copied that entire file again. v1.10.2 removes that second pass.
- The destination is reopened and checked for a real audio sample before any
  recovery part is deleted. A write or verification failure removes the partial
  destination and keeps the local parts for **Retry save**.
- Non-seekable cloud/document providers retain a compatible two-pass fallback.
- Recorder saving now shows a determinate percentage and current part, followed
  by an explicit verification step. Status is recovery-checkpointed; an
  interrupted save restarts from preserved parts, not from an exact byte offset.
- Mux finalization errors now fail safely instead of being swallowed.
- Pause/resume/stop/discard now send commands to the already-running foreground
  service without creating a redundant five-second foreground-start obligation.
  New start/retry/recover commands still use Android's required foreground start.
- Terminal service cleanup is main-thread serialized and guarded by the latest
  Android start id. A delayed stop from a discarded/saved session can no longer
  terminate a new recording started immediately after the Recorder becomes idle.

## How to use

1. Record normally from the **Record** tab, including multi-hour sessions.
2. Tap **Stop and save recording**.
3. Leave Debrief installed while the progress bar shows messages such as
   **Saving audio part 17 of 40** and **Verifying the saved recording**.
4. If Android or the folder provider rejects the write, reopen Recorder and use
   **Retry save** or **Choose another folder**. The protected audio remains local.
5. For the fastest finalization, link a local on-device folder instead of a cloud
   provider that exposes only a non-seekable streaming destination.

## Limitations and edge cases

- A stock recorder can save almost immediately because it writes one final file
  throughout capture. Debrief keeps roughly 8 MiB independently playable parts
  so a crash near the end of a six-hour session does not risk the entire file.
  Making one standard M4A therefore still requires one duration-proportional
  remux/write pass. v1.10.2 removes one of the old two full-file passes; it does
  not make protected multi-hour finalization constant-time.
- Destination storage speed, available space, thermal throttling, and document
  provider behavior still affect save time. A non-seekable provider uses the
  slower compatibility path and is identified by the longer two-stage progress.
- Do not uninstall Debrief or clear its app data while **Save needs attention**
  is present; that removes app-private recovery audio. App upgrades are safe.
- No app can protect audio through force-stop, uninstall, full/failed storage,
  hardware failure, or speech that Android never supplied to the microphone.
- Android 10 or newer is required. The universal APK includes ARM64 and is
  verified for 16 KB memory pages used by the OnePlus 13.
- GitHub APKs are sideloaded, so Play Protect may warn about an unknown developer.
  Install only the APK attached to this repository's release.

## Install and compatibility

Download `Debrief-v1.10.2.apk` and open it on the phone. It is production-signed
to upgrade v1.10.1 in place without removing linked recordings, recovery parts,
transcripts, settings, comments, manual sets, redactions, or speaker names.
