# Debrief v1.11.0 - Private Share Sets

This release adds a privacy-first way to share selected completed conversation
sets with a coach or community. One expiring link can contain up to ten sets
from one recording, including each set's derived audio, transcript, and every
comment inside its time range.

## How to share sets

1. Open a transcribed recording and open **Chapters**.
2. Tap **Select to share**, choose the completed sets, then tap **Review share**.
3. Confirm the exact set order, duration, included comments, and privacy summary.
4. Choose 30, 60, or 90 days. Thirty days is the default. Add an optional PIN
   if the recipient link needs a second access check.
5. Tap **Create link**. Debrief prepares and uploads in the background. If the
   network or app process is interrupted, use **Resume**; completed work is kept.
6. Copy, open, or send the finished link. Each set has a separate player that
   begins at 0:00, followed by its transcript and timestamped comments.
7. Manage links under **Settings -> Cloud sharing**. You can extend an active
   link or revoke it immediately.

## Privacy model

- Debrief never uploads the original recording. It exports only the exact
  selected set ranges into private derived clips.
- Every locally stored redaction is permanently applied to the shared snapshot,
  regardless of the current shield toggle: text becomes `[redacted]` and the
  protected audio interval becomes silence. The local source stays unchanged.
- Only words and comments inside the set's start-inclusive/end-exclusive bounds
  are included. Open/incomplete sets cannot be selected.
- Publication is atomic. The link is inaccessible until every expected private
  object has passed server size and checksum validation.
- The URL is a bearer credential. Anyone who receives a link without a PIN can
  open it until it expires or is revoked. Do not post private links publicly.

## Cloud storage and link management

- **Cloud sharing** shows current tracked bytes against a consistent 10 GB R2
  Standard free-tier reference, active link count, per-link size, expiry, and
  resumable drafts.
- The 10 GB value is a reference rather than an app-enforced quota. Cloudflare
  calculates storage as GB-month from average daily peak use and also has request
  limits. The app labels stale/failed usage refreshes instead of showing a false
  fresh value.
- Expired and revoked links deny transcript, page, and audio byte-range access;
  their cloud objects are deleted. Local history remains visible.
- A share is an immutable snapshot. Revoke and create a replacement to publish
  later transcript, comment, set-boundary, or redaction changes.

## Reliability and security

- Share preparation and multipart upload run as resumable WorkManager foreground
  work. Per-set export and per-part upload checkpoints survive process death.
- Android reconciles server-side object completion and publication after a crash,
  avoiding duplicate links and duplicate uploads.
- Owner and optional-PIN credentials are protected by Android Keystore. Pairing
  codes expire after 15 minutes and can be used only once.
- The Cloudflare Worker hashes bearer/owner tokens, keeps R2 private, rate-limits
  PIN attempts, uses unguessable object keys, validates manifests server-side,
  serves audio with Range support, and applies no-store/no-index security headers.

## Limits and gotchas

- One link supports sets from one recording only, with a maximum of ten completed
  sets and three hours of combined selected audio.
- Every comment inside a selected set is included. Individual comment exclusion,
  recipient comments, reactions, accounts, analytics, and multi-recording links
  are not part of this release.
- There is deliberately no Download button. A browser recipient can still use
  screen recording or network tools; no web player can promise otherwise.
- Share creation needs network access and the one-time Cloudflare owner pairing.
  Recording, playback, annotations, and the local source remain local-first.

## Verification performed before publication

- Android JVM tests, debug lint, Android-test compilation, and release R8 pass.
- Seven Cloudflare Worker integration tests pass against isolated D1/R2 storage;
  TypeScript, dependency audit, and Wrangler production dry run pass.
- The complete device suite passed on Android 11 and Android 15 with true 16 KB
  memory pages, covering the OnePlus 13 compatibility target.
- A conditional live test used a private gitignored M4A fixture through the real
  Android export/WorkManager/Worker/D1/R2 flow. It verified selected-boundary and
  comment filtering, permanent text/audio redaction, publication, unauthenticated
  transcript and audio Range playback, the 10 GB usage reference, revocation,
  object deletion, and immediate public 404 denial.

The APK is production-signed to upgrade v1.10.2 in place. Existing recordings,
transcripts, comments, manual sets, redactions, settings, and recovery data are
preserved by the Room schema migration.
