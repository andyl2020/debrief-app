# Debrief v1.12.2 - Copy complete transcript

This release adds one-tap complete-transcript copy to Android and the cross-platform web/PWA app.

## What changed

- Added **Copy transcript** beside the transcript refresh action on Android and prominently in the web Review header.
- Copies every transcript segment in chronological order as plain text.
- Every line includes its timestamp and current speaker label, including user-renamed speakers: `[0:01] Andy: Hey good to meet you.`
- Copies the transcript exactly as it is intentionally being viewed. Redacted text remains `[redacted]` while redaction mode is enabled; Android Cleaned view includes visible accepted repairs.
- Browser copy uses the secure Clipboard API with a compatibility fallback. Clipboard failure is caught and directs the user to the existing Markdown export instead of crashing or reporting false success.
- Android marks the copied transcript as sensitive so supported system clipboard previews do not expose private conversations.
- Updated official GitHub build actions and Cloudflare development dependencies to remain compatible with current runners and resolve newly disclosed Vitest/Sharp advisories. The deployed sharing protocol and stored data format are unchanged.

## How to use it

Open any fully transcribed recording in **Review** and tap **Copy transcript** (the overlapping-pages icon on Android). Paste into Messages, email, Notes, a document, or a coaching tool. The entire transcript is copied in one operation with timestamps and speaker labels.

If the recording contains private redactions, leave the shield/redaction mode on before copying. Turn it off only when you deliberately want the original transcript on the clipboard.

## Limitations and gotchas

- Clipboard systems keep one current clip. Writing “part 2” automatically would replace “part 1,” so Debrief performs one complete copy rather than unreliable multi-part writes.
- Android and browser documentation does not define one portable maximum length for plain clipboard text. A destination application can impose its own paste limit even after Debrief copied successfully. Use **Export Markdown** if an unusually long transcript cannot be pasted into the destination.
- Web clipboard writes require a secure HTTPS page and a user action. Both official Debrief web deployments use HTTPS.
- Copy contains transcript segments, timestamps, and speaker labels. It intentionally excludes comments; **Export Markdown** includes comments.
- Clipboard contents can be read by the operating system and, depending on platform policy, other foreground apps. Paste private transcripts promptly and replace the clipboard afterward when needed.
- This release does not modify audio, transcript rows, comments, sets, redactions, cloud data, or database schema.
- Android 10 or newer is required. The universal APK remains compatible with the OnePlus 13 and validated for modern 16 KB-page devices.
- On iPhone, Apple can suspend PWA recording when the screen locks or another app takes the microphone; transcript copy and the remaining review tools are unaffected.

## Install or upgrade

Android users can install `Debrief-v1.12.2.apk` directly over the repository-signed v1.12.1 build without clearing data. A debug or independently signed build must be removed first because Android rejects signing-identity changes.

iPhone and desktop users receive the PWA update automatically. If an installed PWA still shows the earlier version after deployment, fully close it and reopen once while online so the service worker can activate the new assets.
