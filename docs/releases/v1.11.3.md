# Debrief v1.11.3 - Reliable recording rename

This patch fixes recording rename failures in Library and makes the save flow
transaction-like from the user's perspective. It preserves all v1.11.2 data,
features, and cloud-sharing behavior.

## What changed

- Replaced AndroidX `SingleDocumentFile.renameTo()`, which is unsupported for
  single document URIs, with Android's `DocumentsContract.renameDocument()`.
- Stores the renamed URI returned by the phone's document provider; this is
  required because some providers change the URI when a file is renamed.
- Moves rename and search-index database work off the main thread.
- Keeps the rename dialog open while saving and on errors, with readable
  permission, provider, missing-file, and collision guidance.
- Edits only the base filename while showing and preserving the existing audio
  extension.
- Attempts to restore the old physical filename if the local database update
  unexpectedly fails.

## How to use it

In **Library**, tap the pencil beside a recording. Change the name before the
displayed extension and tap **Save**. Wait for the dialog to close; the Library,
search metadata, and recording-bound sidecars then use the new name.

If Debrief says it no longer has permission, use **Change** in Library to re-link
the recordings folder and retry. If the storage provider does not support rename,
move the recording to a writable local folder. A filename already used in the
same folder may need a different name.

## Compatibility, limitations, and gotchas

- Android 10 or newer is required. The universal APK includes ARM64 and x86-64
  native libraries and is validated for modern 16-KB-page devices such as the
  OnePlus 13.
- This patch does not change the database schema, recording format, source audio,
  transcript, annotations, cloud API, pairing credentials, or signing identity.
  It upgrades directly over v1.11.2 without clearing app data.
- Renaming changes the real source filename and its Debrief sidecars. It does not
  create a copy. The original extension remains unchanged.
- Android storage providers control rename support and collision behavior.
  Debrief reports rejection without discarding the existing library record.
- Uninstalling Debrief still removes app-private data. Keep the recording and its
  paired sidecars together for reinstall recovery.
- GitHub sideloads may trigger Play Protect's unknown-developer warning. Install
  only the signed APK attached to this repository's release.

## Install or upgrade

Download `Debrief-v1.11.3.apk` from this release and open it on the phone. A
repository-signed v1.11.2 installation upgrades in place and retains local data.
An independently signed/debug build must be removed first because Android will
reject a different signing identity.
