# Debrief v1.10.1 — Samsung recorder notification cleanup

This patch fixes recorder notifications that could remain visible on Samsung and
other Android devices after recording foreground work had ended. It also stops
Debrief from reposting the active notification every half second.

## What changed

- A failed linked-folder save no longer detaches the notification. Android
  documents detached foreground notifications as intentionally remaining after
  the service stops; Debrief now removes them.
- Stop, discard, successful save, failed save, empty recovery, and start failure
  all use foreground-notification removal plus an explicit notification cancel.
- When no recording is active, service startup clears notification id 8120 so
  v1.10.1 also cleans up a stale notice left by an older installed build.
- The active timer now uses Android's built-in notification chronometer. The
  recorder no longer calls `notify()` every 500 ms, so Samsung System UI cannot
  interpret timer refreshes as a new card after a dismissal.
- Pause/resume, automatic call/storage pauses, recorder recovery, rollover, and
  microphone-silence status changes still update the notification when visible.
- Android 13+ individual swipe dismissal remains session-scoped. Capture,
  pause/resume, final save, and locally recoverable save failures continue to work.

## How to use

1. Record normally from the **Record** tab.
2. On Android 13 or newer, swipe the active notification away if desired; reopen
   Debrief for pause/resume/Stop controls.
3. On a Galaxy S10 running Android 12, leave the required active notification in
   place while recording. Tap **Stop** or discard the recording in Debrief; the
   notification is then removed.
4. If an older Debrief build left a stale notification, install/open v1.10.1.
   With no active session, the stale recorder notification is cancelled.

## Limitations and edge cases

- Android 12 and older treat an active foreground-service notification as
  non-dismissible. A Galaxy S10's final Android release is Android 12. Removing
  that notification during capture would require dropping foreground status,
  making a long microphone recording vulnerable to OEM/process termination.
  Debrief intentionally keeps the reliable service and removes its notice as soon
  as foreground work ends.
- Android 13+ can still list Debrief under **Active apps** after its individual
  notification is dismissed because recording is genuinely continuing.
- A save failure preserves finalized audio in app-private storage. Reopen Recorder
  and use **Retry save** or **Choose another folder**; do not uninstall or clear
  app data while recovery audio is present.
- No Android app can preserve audio through force-stop, uninstall, reboot/power
  loss, revoked permission, full/failed storage, hardware failure, or speech the
  OS never delivered.
- Android 10 or newer is required. The universal APK includes ARM64 and is
  verified for 16 KB memory pages used by the OnePlus 13.
- GitHub APKs are sideloaded, so Play Protect may warn about an unknown developer.
  Install only the APK attached to this repository's release.

## Install and compatibility

Download `Debrief-v1.10.1.apk` and open it on the phone. It is production-signed
to upgrade v1.10.0 in place without removing linked recordings, transcripts,
settings, comments, manual sets, redactions, speaker names, or recovery backups.
