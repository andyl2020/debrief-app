# Debrief v1.11.1 - Stable Share Sets startup

This patch fixes the crash that could occur immediately after tapping **Create
private link** on Android 14 and 15 devices, including the OnePlus 13.

## Root cause and fix

Share Sets correctly declared WorkManager's `dataSync` foreground-service type
and permission in the Android manifest, but its runtime `ForegroundInfo` used
the legacy two-argument constructor and therefore supplied service type `none`.
Android 14+ rejects that combination for target SDK 35 with a fatal
`InvalidForegroundServiceTypeException`.

v1.11.1 passes `FOREGROUND_SERVICE_TYPE_DATA_SYNC` at runtime, matching the
manifest. Foreground startup now also occurs inside the worker's guarded failure
path so ordinary setup failures become visible draft errors instead of escaping
the share workflow.

## Recovery behavior

Opening **Settings -> Cloud sharing** after an interruption reattaches unfinished
snapshot, upload, and publish work with WorkManager's KEEP policy. Existing
checkpoints and remote draft IDs are reused; healthy active work is not replaced.
This lets a draft left by the v1.11.0 crash resume after upgrading.

## Verification

- The old build reproduced the fatal service-type exception on Android 15 with
  true 16 KB pages.
- The fixed build passes a direct runtime foreground-type assertion.
- The same private gitignored M4A then passed the real Android-to-production
  flow: derived clip export, permanent redaction, transcript/comment isolation,
  upload, public byte-range playback, revoke, object deletion, and an empty crash
  buffer.
- JVM tests, debug lint/build, and Android-test compilation pass before final
  release verification.

All v1.11.0 Share Sets behavior and the production Cloudflare service remain
compatible. The database schema and account credentials are unchanged.
